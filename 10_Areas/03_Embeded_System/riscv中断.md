# 📝 Core
## RISC-V 中断体系架构
### 中断的定义
在riscv中，中断和异常虽然都会打破处理器正常的指令执行流程，但它们在触发源、触发时机、处理目标上存在明显的差异

中断是由处理器外部的硬件设备或特定内部事件（如定时器）发出的异步信号，用于通知处理器有紧急任务需要处理。

例如，当我们在使用计算机时，按下键盘的某个按键，键盘控制器就会产生一个中断信号，通知处理器有按键输入需要处理；或者硬盘完成数据读取操作后，也会发送中断信号告知处理器数据已准备好。这些中断信号随时可能到来，与处理器当前执行的指令没有直接关联，是异步发生的。一旦处理器检测到中断信号，并且中断是被使能的，就会暂停当前的任务，转而去执行相应的中断服务程序，处理完中断后再返回原来的任务继续执行。

异常则是在处理器内部执行指令过程中，由当前指令引发的同步事件。它通常表示出现了错误或需要进行特殊操作。比如当处理器执行到一条未定义的指令，即遇到非法指令异常；或者访问内存时，地址未正确对齐，产生访存错误异常；又或者执行到用于调试的 EBREAK 指令，触发断点异常等。这些异常都是与当前正在执行的指令紧密相关，在指令执行的过程中被检测到。

当异常发生时，处理器会暂停当前指令的执行，保存相关的上下文信息，然后跳转到对应的异常处理程序，对异常情况进行处理，处理完毕后根据具体情况决定是返回原指令重新执行（如缺页异常处理完成后尝试重新执行触发异常的指令），还是终止执行。

### riscv的特权模式
RISC-V 的特权模式决定了**代码能访问哪些资源，以及中断和异常由谁处理**。核心关系可以概括为：

1. **M 模式 (Machine mode 机器模式) 权限最高**  
	能访问全部硬件和控制寄存器。所有中断和异常默认先归 M 模式处理；M 模式也可以通过委托机制，把部分事件交给较低特权级处理。
2. **S 模式 (Supervisor mode 监督模式) 主要运行操作系统内核**  
    负责虚拟内存、进程和外设管理。被 M 模式委托的中断或异常，可以直接由 S 模式处理，而不必进入 M 模式。
3. **U 模式 (User mode 模式模式) 主要运行应用程序**  
    权限最低，不能直接控制硬件。应用程序发生异常、执行 `ECALL` 或需要操作系统服务时，会陷入 S 模式或 M 模式处理。
4. **中断和异常会触发特权级切换**  
    事件发生后，处理器根据事件类型和委托配置，自动进入相应的高特权模式，并跳转到对应的处理程序。
5. **处理完成后返回原执行环境**  
    M 模式通过 `MRET` 返回，S 模式通过 `SRET` 返回，恢复原来的特权级和程序执行位置。

补充：
- 中断和异常是处理器从当前执行环境进入更高权限处理程序的重要入口，而委托机制决定事件最终由 M 模式还是 S 模式处理。
- 除了上述提到的三种模式，还有一种H模式 (Hypervisor 虚拟化模式)，H 扩展通常不是一个完全独立、与 M/S/U 并列执行的传统特权级，而是在虚拟化扩展中引入 HS、VS、VU 等运行状态。
- 外设产生中断，若该中断被配置为在监督模式处理，处理器会自动从当前模式切换到监督模式

### 中断源的分类
在riscv架构当中，中断源有很多，主要的有：外部中断、定时器中断、软件中断

1. **外部中断**
	外部中断由处理器核心之外的硬件模块或外设产生，例如：
	- 网卡
	- UART
	- GPIO
	- DMA
	- PCIe 控制器
	- 存储控制器
	
	当外设需要处理器提供服务时，会产生中断请求。例如，网卡收到新的数据包后，可以通过中断通知处理器读取和处理数据。
	
	在采用传统 RISC-V PLIC 架构的系统中，外设中断通常不会直接连接到处理器核心，而是先进入 PLIC。
	
	其基本路径为：外设 → PLIC → 处理器core → 中断处理程序
	
	PLIC 主要负责：
	
	- 收集多个外设的中断请求
	- 设置各中断源的优先级
	- 屏蔽或使能中断源
	- 在多个待处理中断之间进行仲裁
	- 将选中的中断通知给处理器核心
	
	因此，外部中断可以理解为：==外设通过中断控制器，请求处理器执行相应的中断服务程序。==



1. **定时器中断**
	定时器中断由系统定时器产生。
	
	系统中通常存在一个持续递增的时间计数值，以及一个比较值。当当前时间达到或超过比较值时，定时器模块会向处理器发出定时器中断。
	
	以传统 RISC-V 平台为例，可以抽象为：mtime >= mtimecmp → 触发机器模式定时器中断
	
	其中：
	- `mtime`：持续递增的时间计数器
	- `mtimecmp`：定时器比较值
	
	定时器中断常用于：
	
	- 操作系统时钟节拍
	- 任务调度
	- 时间统计
	- 超时检测
	- 延时和定时任务
	- 周期性任务
	- 睡眠任务唤醒
	
	例如，操作系统可以周期性设置下一次定时器中断。当中断到来时，内核更新系统时间，并判断是否需要切换当前任务。
	
	需要注意：
	**定时器中断虽然最终送入处理器核心，但定时器本身通常属于平台级硬件，并不一定集成在 CPU 核内部。**


2. **软件中断**
	软件中断由软件主动触发，主要用于处理器核心之间的通信。

	在多核系统中，一个处理器核心可以通过写入特定的内存映射寄存器，触发另一个核心的软件中断。

	其基本过程可以涵盖为：Hart 0 写入软件中断寄存器 → Hart 1 收到软件中断 → Hart 1 执行相应处理
	
	软件中断常用于：
	
	- 核间通信
	- 核间任务通知
	- 请求其他核心执行调度
	- TLB 刷新通知
	- 多核系统同步
	- 唤醒处于等待状态的核心
	
	在传统 RISC-V 平台中，软件中断常通过 CLINT 中的 `msip` 寄存器触发。某个 Hart 对目标 Hart 对应的 `msip` 置位后，目标 Hart 会收到机器模式软件中断。
	
	因此，软件中断可以理解为：**软件通过写硬件寄存器，人为产生一个中断请求，通常用于 Hart 之间传递通知。**


3. **软件中断与 ECALL 的区别**
	软件中断和 `ECALL` 容易被混淆，但两者本质不同。
	
	软件中断属于**异步中断**。它通常通过写入中断控制寄存器触发，用于处理器核心之间的通信。

	例如：Hart 0 写 msip → Hart 1 收到软件中断

	What is `ECALL`?

	`ECALL` 属于**同步异常**，不是软件中断。
	
	程序执行 `ECALL` 指令时，处理器会立即产生 Environment Call 异常，并进入更高特权级的异常处理程序。
	
	例如，用户程序发起系统调用：
	U Mode 执行 ECALL → 生 Environment Call 异常 → 进入 S Mode 或 M Mode → 执行系统调用处理程序

	**两者的主要区别如下：**

| 对比项           | 软件中断     | ECALL       |
| ------------- | -------- | ----------- |
| 类型            | 异步中断     | 同步异常        |
| 触发方式          | 写软件中断寄存器 | 执行 ECALL 指令 |
| 常见用途          | 核间通信     | 系统调用、固件服务调用 |
| 是否与当前指令直接相关   | N        | Y           |
| 是否属于interrupt | Y        | N           |

三种模式的对比

| 中断类型  | 产生来源      | 常见用途      | 典型管理模块           |
| ----- | --------- | --------- | ---------------- |
| 外部中断  | 外设或片上硬件模块 | 外设事件通知    | PLIC             |
| 定时器中断 | 系统定时器     | 调度、计时、超时  | CLINT 或其他定时器模块   |
| 软件中断  | 软件写寄存器触发  | 核间通信、任务通知 | CLINT 或其他 IPI 模块 |


### 向量模式
在单向量模式下，所有的中断和异常都共享同一个处理入口，处理程序需要根据 mcause 寄存器的值来判断具体的中断或异常类型，然后进行相应的处理。这种模式适用于一些简单的系统，其优点是硬件实现简单，成本较低。而在多向量模式下，不同的中断和异常类型可以有各自独立的处理入口，这样可以提高中断处理的效率，减少处理时间。例如，在一个复杂的多外设系统中，使用多向量模式可以让不同外设的中断迅速跳转到对应的处理程序，加快系统的响应速度。通过设置 mtvec 寄存器，可以根据系统的需求灵活选择中断向量模式，优化系统的性能。下面通过代码演示如何配置 mtvec 寄存器，指定中断入口并选择对应的工作模式。
