# 1.项目概览

这是 **TaiShan 芯片固件（FW）的 QA 集成测试工程**：在 Windows 上用 pytest 驱动一块真实的 TaiShan EVB 板，通过 wAPI、UART 固件 shell、MSS 寄存器三条通道下发命令并校验结果，最后产出名为 `FW_QA_Taishan_IntegrationTest_<日期>` 的 Allure HTML + xlsx 报告。

- **被测对象**：TaiShan 8-lane SerDes/光模块 DSP 芯片的固件。仓库也兼容 WLXP0400 / WLXP0800 / SongShan 等板型，由环境变量 `WLOP_CHIP_TYPE` 选择。
- **陪测设备**：一块 SongShan 板可作为 BERT（误码仪）对打，`HW_env` 环境变量标记当前硬件环境（`BERT`、`Self-collection`、`G800` 等）。
- **测试代码全部在 `test_integration/`**，仓库根目录的 `wapis_cmds.py`、`core.py`、`board.py`、`libs/`、`ts_mss_ftdi/`、`validation/` 都是厂商/内部提供的底层依赖，测试框架只调用它们。

**以上三类测试被分为三条通道**

| 测试类型        | 用例形式                      | 位置                                       | 下发通道                                                                              |
| ----------- | ------------------------- | ---------------------------------------- | --------------------------------------------------------------------------------- |
| wAPI 功能用例   | YAML 脚本（197 个，23 个功能目录）   | `test_integration/tests/wapi_cases/`     | `wapis_cmds.WAPISCmds` → `libwapis.dll` → `libwwccpadapt.dll` → FTDI USB（I2C/SPI） |
| 寄存器级步骤      | YAML 中的 `mss:` 步骤         | 同上                                       | `validation/api` → `ww_adapt` 驱动直接读写 CSR                                          |
| Datapath 用例 | 纯 Python pytest（12 个测试文件） | `test_integration/tests/datapath_cases/` | 串口（pyserial）→ 固件 shell 的 `datapath` 子命令                                           |

核心设计：**用例是数据（YAML），框架是引擎**。`framework/engine.py` 读 YAML、校验、按步调用 `ww_*` 函数并按 `expect` 断言；新增 wAPI 接口不需要写任何 Python 包装代码。

**四条控制通道最终都会落到 TaiShan EVB，BERT会走独立的子进程**，具体的分配参考看板![[01_设计框图.canvas]]

# 3. 环境依赖与运行入口

唯一的运行入口是 **`test_integration/run.py`**，它只是给 `pytest.main()` 拼参数，并在 `--allure` 时生成报告。请**在仓库根目录运行**：`libwwccpadapt.dll` 按相对路径 `conf/ccp_adapt.json` 读配置，工作目录不对就连不上板子。

## 3.1 硬件

- TaiShan EVB：板上 FT2232H 的 A 通道走 JTAG（复位 / AVDDO），B 通道走 SPI（wAPI）。`board.py` 里序列号**写死**为 `FTBVCBGD`，换板要改这里。
- DUT UART：USB 串口线，仅 datapath 用例需要。
- 可选 SongShan 板作 BERT：由 `drivers/songshan/ss_wapi/ss_server.py` 在独立子进程中控制（一个进程的 ccp 栈只能持有一个 FTDI 设备）。

## 3.2 软件

- Windows + Python 3.12（`validation/api/soc_routines` 里的 .pyd 是 cp312 构建）。
- 仓库**没有 requirements.txt**（README 提到但不存在）。从 import 推出的依赖：

```bash
pip install pytest allure-pytest pytest-check pyyaml pyserial openpyxl pillow matplotlib numpy pandas scipy
```

- Allure CLI（需 Java）：生成 HTML 报告用；没装时 run.py 只告警并打印手动命令。
- draw.io 桌面版（可选）：流程图导出 PNG 用，没有就回退到 matplotlib 引擎。

## 3.3 环境变量

`setup_env.sh` 是交互式 bash 脚本，很多路径（`astro/`、`libs/libwapis/<project>/<board>`）在本仓库里并不存在，适合只当参考。在 Windows 上真正需要的是下面这几个：

|   |   |   |
|---|---|---|
|变量|示例值|作用|
|`PROTOCAL_LIB_PATH`|仓库根目录|必填：从 `<值>/libs/` 加载 libwapis.dll / libwwccpadapt.dll（注意拼写是 PROTOCAL）|
|`WLOP_CHIP_TYPE`|`TaiShan`|必填：板型，决定复位方式、lane 数（8）、报告目录名|
|`PYTHONPATH`|`<根目录>;<根目录>\ts_mss_ftdi\py`|必填：让 `wapis_cmds`、`board`、`ts_board_init`、`jtag_driver` 可导入|
|`HW_env`|`BERT`（默认）/ `Self-collection` / `BERT,G800`|硬件环境标签，决定哪些用例/步骤执行，详见第 5 节|
|`UART_PORT` / `UART_BAUD`|`COM8` / `115200`|datapath 串口，默认 `COM30`；也可用 `--uart-port` / `--uart-baud`|
|`WAPIS_CMDS_PY`|（可选）|schema 校验去哪里解析 API 名，默认根目录 `wapis_cmds.py`|
|`PROJ_VARIANT`|（可选）|validation 的板型配置，不设则取字母序第一个 `apms_saints_8lane`|

PowerShell 下一次性设置示例：

```powershell
cd D:\WorkSpace\coding\taishan_wapis_cp
$env:PROTOCAL_LIB_PATH = $PWD.Path
$env:WLOP_CHIP_TYPE = "TaiShan"
$env:PYTHONPATH = "$PWD;$PWD\ts_mss_ftdi\py"
$env:HW_env = "BERT"
```

## 3.4 常用命令

```bash
python test_integration/run.py -m prbs                  # 按 marker 跑（marker 由目录名自动生成）
python test_integration/run.py -m "diag or fec" --allure  # 跑完生成 Allure HTML + xlsx
python test_integration/run.py -k "chip and info"       # 按用例名（YAML 的 name）过滤，多个词用 and 连接
python test_integration/run.py -k datapath_cases --uart-port COM8   # 只跑 UART datapath 用例
python test_integration/run.py -k test_script           # 只跑 YAML 用例
python test_integration/run.py --collect-only -q        # 不碰硬件，列出全部用例
python test_integration/run.py -m prbs --lf             # 未知参数原样透传给 pytest
```

- 不加任何过滤会跑全部 YAML + datapath 用例，耗时很长。
- README 里的 `-k datapath` 也会命中 `Datapath sync …` 这类 YAML 用例（-k 是子串匹配），精确选择用 `-k datapath_cases`。
- `-s` 必须保留：FTDI/ccp C 库与 pytest 输出捕获不兼容，pytest.ini 已默认带上。

# 4. 核心框架与公共模块

YAML 用例的一生：`test_wapi_scripts.py` 把每个 .yaml 变成一个 pytest 参数 → `engine.run_script()` 校验并选出匹配 `HW_env` 的变体 → 逐步执行 `api` / `mss` / `builtin` → `expect.check_expect()` 断言。各模块职责如下。

## 4.1 收集：`tests/wapi_cases/test_wapi_scripts.py` + `conftest.py`

- 收集阶段只读 YAML，不 import `wapis_cmds`、不加载 DLL，所以 `--collect-only` 不需要硬件。
- 用例 ID = YAML 的 `name`（重名会冲突，注意保持唯一）。
- **marker 从路径自动推导**，不用写在 YAML 里。例如 `polarity/line_egress/line_egress_polarity_case1.yaml` 得到：`line_egress_polarity_case1`、`line_egress_polarity`、`polarity`、`line_egress`。datapath 用例同理（`stat/test_stat_cases.py` → `stat`、`test_stat_cases`）。
- `conftest.pytest_configure` 自动注册这些 marker；`pytest_collection_modifyitems` 按目录层级打 Allure 的 parentSuite / suite / subSuite 标签。

## 4.2 引擎：`framework/engine.py`

- `run_script(path, runtime)`：一个文件可用 `---` 分隔多个变体，每个变体有自己的顶层 `env`；恰好一个匹配才执行，零个匹配 → skipped，多个匹配 → 报错。
- 注入的运行时变量：`$board`、`$total_lanes`（8）、`$lane_mask`（0xFF）、`$env`。
- `dispatch_api`：用 `inspect.signature` 自适应 `wapis_cmds` 的函数签名——单个 `p_*` 参数 → 整个 args 字典传入并在调用后作为输出；标量参数按参数名绑定；缺省的 `opts` / `p_*` 自动建空字典并捕获为输出；返回 `None` 视为 0。**新增 wAPI 不用写任何包装。**
- `dispatch_mss`：`mss:` 步骤依次在 `lib_1p3` → `lib` 的 config/status/bist/adv_diag 类 → `api` 模块 → MSS 对象自身方法里找函数；返回 dict 当输出，返回 int 当 ret。
- 步骤修饰：`foreach: lane`（展开出 `$lane` / `$lane_bit`）、`foreach: {var, in}`、`loop: {var, in} + steps`（子步骤块）、`env`（步骤级跳过）、`save_as`。
- 每步是一个 Allure step（`log` 除外），输出以 JSON 附件挂上。

## 4.3 断言：`framework/expect.py`

|   |   |   |
|---|---|---|
|写法|失败类型|行为|
|`expect: {ret: 0}`（默认）或任何整数|硬失败 `StepFailed`|立即终止脚本|
|`expect: {ret: {eq: 1}}` 等运算符|软失败（pytest-check）|记录并继续|
|`expect: {fields: {...}}`|软失败|子集匹配，支持 eq/ne/ge/le/gt/lt/in；单元素 tuple 自动解包|

软失败会以 `SOFT FAILURE` 附件钩在当前 Allure 步骤上，报告里能直接看到哪一步不匹配。

## 4.4 其它模块

- `context.py`：变量查找优先级 foreach/loop 局部 > `save_as` > 脚本 `vars` > 运行时变量；整个字符串是 `$x.y` 时保留原类型，嵌在字符串里时转 str。
- `schema.py`：用 AST 从 `wapis_cmds.py` 和 `validation/api/*.py` 提取合法的 API / mss 名，拼错会提示“did you mean”。校验发生在用例执行时，不是收集时。
- `runtime.py`：`Runtime` 持有 `wapis`（WAPISCmds）、`board`（board.py）、`mss`（validation `init_driver(ww_adapt)`）三个**懒加载**句柄；`reset()` = 释放 wapis → `board_chip_reset()` → 等 2s → 重建 wapis。每个用例新建一个 Runtime，结束时 release。
- `uart/`：`DutShell` 发命令并等 `shell>` 提示符，超时会发回车探活并重试 2 次；`Datapath` 把 `datapath <子命令>` 封成方法；`parsers.py` 解析 BIST/BER/stat/xbar_map 输出并找 `ERROR:|TIMEOUT:|failed` 行。

## 4.5 Builtin 一览

扩展方式：在 `framework/builtins_ext/` 新建 .py，用 `@builtin("name")` 注册，签名固定 `fn(args, ctx, runtime)`，导入时自动扫描。

|   |   |   |
|---|---|---|
|builtin|作用|用例中使用次数|
|`log`|打印信息（支持 `$var`），不计步号|275|
|`reset`|芯片复位；`HW_env` 含 BERT 时由 bert.py 重写：先挂起 SongShan、复位、恢复，再把 BERT 置为 op mode 6 + host PRBS gen/chk 全开 + 默认 TX FIR|197|
|`set_op_mode`|`ww_set_chip_work_mode` → 等 2s → AVDDO 上电 → `ww_set_line_drive_mode(0)`|185|
|`sleep`|等待|147|
|`read_csr` / `write_csr`|按绝对地址读写 CSR（经 mss HAL）|55|
|`check_ber`|本板 PRBS checker 按 lane 算 BER；`normal` 必须锁定，`invert` 必须不锁|26|
|`bert_prbs_on` / `bert_prbs_off` / `bert_check_ber` / `bert_set_op_mode` / `bert_get_tx_fir` / `bert_set_tx_fir`|操作 SongShan BERT|46|
|`wait_until`|轮询某个 API 直到字段等于期望值，超时硬失败|12|
|`check_snr` / `snr_stability` / `snr_update_time`|SNR（固件返回 dB×256）检查与稳定性|8|
|`ltp_baseline` / `ltp_update_time` / `ltp_stability`|LTP 相关统计|6|
|`check_lane_rate`|从 PLL 寄存器反推每条 lane TX/RX 速率，对比 op mode 期望值|1|
|`board_avddo_en`、`decode_efuse_chip_id`、`skip`|AVDDO 上电、解码 chip_id、整个用例标记跳过|4|

op mode 与 lane 速率的对应表在 `builtins.py` 的 `_OP_MODE_LANE_RATE_GBPS`（mode 6 = 1×106G，10 = 1×53G，8/9 = gearbox，1/11 = 4×/8×106G 等），用新 mode 前要先补这张表。

# 5. 测试用例组织

用例分两套：197 个 YAML wAPI 用例按功能目录归类，52 个 Python datapath 用例按固件 `datapath` 子命令归类；目录名就是 marker，可直接 `-m <目录名>` 运行。

## 5.1 wAPI YAML 用例（`tests/wapi_cases/`）

|   |   |   |
|---|---|---|
|目录|用例数|覆盖内容|
|`diag/`|38|chip_info、wapi_version、status、temperature、register、snr、sndr、tracebuffer、flash_log、atest、mpi、ga、eqbk_pause、start_eq、slice_target、optical_fiber|
|`prbs/`|21|PRBS gen / chk 配置、误码注入、锁定与计数|
|`fec/`|19|prbs_prefec、sim_prefec、traffic_fec（含 `mss:` 寄存器交叉校验）|
|`lane_config/`|16|host/line × ingress/egress lane 配置|
|`polarity/`|16|四个方向的极性|
|`vcsel/`|15|VCSEL driver：burn_in、ibias、ibleed、idac、irterm|
|`squelch/`|10|host_ingress / line_egress squelch|
|`link_status/`、`output_status/`|8 + 8|链路状态、输出状态|
|`operating_mode/`、`power_mode/`|6 + 5|工作模式、功耗模式|
|`ltp/`、`clk/`、`datapath_sync/`、`line_drive_mode/`|5 + 4 + 4 + 4|LTP、时钟、datapath 同步、线路驱动模式|
|其余 8 个目录|18|lanes_map、loopback_mode、sigdet_eq_delay、tx_fir_target_code、line_tx_dpd、stability、rx_optimal_config、common_cmd|

典型 YAML 用例的流程是「reset → set_op_mode → set → get 按 lane 校验 → 恢复」，例如 `prbs/gen/prbs_gen_case1.yaml`：

```yaml
name: "PRBS gen set/get strict match (config and error inject)(case1)"
env: [Self-collection, BERT]          # 两种硬件环境都跑
steps:
  - builtin: reset
  - builtin: set_op_mode
    args: {mode: 6}
  - api: ww_set_prbs_gen_config
    args: {lane_mask: 0xff, side: 1, enable: 1, pattern_type: 6, symbol_swap: 0, udp: [0, 0, 0, 0]}
    expect: {ret: 0}                  # ret 不对 → 立即终止
  - api: ww_get_prbs_gen_config
    foreach: lane                     # 展开 8 次，$lane_bit = 1<<lane
    args: {lane_mask: $lane_bit, side: 1, enable: 0, pattern_type: 0, symbol_swap: 0, udp: [0, 0, 0, 0]}
    expect:
      ret: 0
      fields: {enable: 1, pattern_type: 6, symbol_swap: 0}   # 不匹配 → 软失败，继续
```

约定：`side: 0` = LINE，`side: 1` = HOST；get 类 API 要把结构体所有字段都写上（用来打包请求）。寄存器级校验用 `mss: switch_dev` + `mss: <函数>` 或 `builtin: read_csr`。

## 5.2 UART datapath 用例（`tests/datapath_cases/`）

|   |   |   |
|---|---|---|
|目录|用例数|内容|
|`work_mode/`|7|经 UART 配置 6 种 work mode 并用 wAPI 回读；首条 datapath 命令自动 bring-up|
|`stat/`|6|各 mode 下 `datapath stat` 的 rx/tx 状态|
|`en/`|6|datapath 使能全开/全关与逐 DP 切换|
|`pstate/`|6|逐 DP 下电/上电后 BER|
|`post_xbar_lb/`|6 + 4|host 侧 post-xbar 环回；另 4 个叠加 lane map|
|`nep_lb/`|6 + 4|line 侧 NEP 环回；另 4 个叠加 lane map|
|`xbar/`|4|lane map 覆盖（排列在 `xbar_map.py` 里生成）|
|`bist_gen/`、`bist_chk/`、`ber_chk/`|1 + 1 + 1|DP0 的 BIST 发生器、检查器、BER 查询|

大部分 datapath 文件是「一个私有 `_xxx_case()` + 每种 work mode 一个 `test_xxx_caseN`」的写法，覆盖 mode 6/10/9/8/1/11。通用流程：

1. `require_bert_env(runtime)`：需要外部打流的用例要求 `HW_env` 含 `BERT`。
2. `reset_dut()`：调 `reset` builtin（含 BERT 默认状态恢复），再等串口提示符。
3. 如需切换 BERT 速率：`bert_prbs(off)` → `bert_op_mode(10)` → `bert_prbs(on)`。
4. `set_work_mode()`（经 UART）或 `set_work_mode_wapi()`（经 wAPI），然后 AVDDO 上电。
5. 发 datapath 子命令，用 `check_command()`（无 ERROR/TIMEOUT 行、含期望标记）和 `check_bist()` / `bert_ber()` 判定。
6. `run_dp_steps()` 把逐 DP 的失败汇总后统一断言，一个 DP 失败不会阻断其它 DP。

fixture（`datapath_cases/conftest.py`）：`dut_shell`（session 级，启动时探测提示符）、`datapath`、`runtime`（函数级）。各子命令的拓扑、超时和判定规则详见 `datapath_test_guide.md`，但那份文档描述的是另一个独立脚本 `uart_shell_datapath_test.py`（不在本仓库），只能作为固件命令语义的参考。

# 7. 如何新增用例

绝大多数新用例只需要新增一个 YAML 文件，不动任何 Python。

### 7.1 新增 wAPI YAML 用例

1. 在 `tests/wapi_cases/<功能>/[<子方向>/]` 下新建 `<名字>_caseN.yaml`。路径会自动变成 marker 和 Allure suite，按现有命名习惯放。
2. 拷一个同目录的用例当模板（README 提到的 `templates/set_get_readback.yaml` 已不存在）。
3. 填唯一的 `name`（就是用例 ID、报告里的名字和流程图 PNG 文件名）和 `env`。
4. `api:` 写 `wapis_cmds.py` 里的方法名；字典参数直接写结构体字段，标量参数用参数名做 key。不确定字段时去看函数上方注释里的 C 结构体。
5. 本地先跑 `python test_integration/run.py -k "<name 里的关键词> and <另一个关键词>"`；API 名拼错会在执行时报 `does not exist, did you mean ...`。

常用写法速查：

```yaml
name: "Xxx set/get(case1)"
env: [Self-collection, BERT]
vars: {mode: 6}                         # 脚本变量，用 $mode 引用
steps:
  - builtin: reset
  - builtin: set_op_mode
    args: {mode: $mode}
  - api: ww_get_snr_val
    foreach: lane                        # 展开 8 次，提供 $lane / $lane_bit
    args: {lane_mask: $lane_bit, side: 1, snr: 0}
    save_as: snr                         # 后续用 $snr.snr
    expect: {fields: {snr: {ge: 4608}}}  # dB*256，软失败
  - loop: {var: m, in: [6, 10]}         # 子步骤块
    steps:
      - builtin: set_op_mode
        args: {mode: $m}
  - builtin: bert_prbs_on
    env: BERT                            # 步骤级环境过滤
```

同一用例在不同硬件环境下步骤不同时，用 `---` 写多个文档，各自带不重叠的顶层 `env`。

## 7.2 新增 builtin

当一组操作需要计算、轮询或跨多个 API 时，在 `framework/builtins_ext/` 新建 .py：

```python
from framework.builtins import builtin

@builtin("wait_ready")
def wait_ready(args, ctx, runtime):
    ...  # runtime.wapis / runtime.board / runtime.mss 可用；返回 dict 可被 expect.fields / save_as 使用
```

硬失败 `raise StepFailed(...)`；软失败参考 `check_ber` 的 `attach_soft_failure` + `with check(): assert False`。

## 7.3 新增 datapath 用例

1. 放到 `tests/datapath_cases/<子命令>/test_<子命令>_cases.py`（最近的习惯是一个文件内按 work mode 写多个 `test_xxx_caseN`）。
2. 用 fixture `datapath, dut_shell, runtime`，组合 `helpers.py` 里的 `reset_dut / set_work_mode / check_command / check_bist / bert_* / run_dp_steps`。
3. 加 `@allure.title(...)`，否则报告里只显示函数名。
4. 固件新增子命令时，先在 `framework/uart/datapath.py` 加方法，输出需要结构化时在 `parsers.py` 加纯函数解析器。

## 8.3 建议的上手路径

1. 按 3.3 设好环境变量，在根目录跑 `python test_integration/run.py --collect-only -q`，确认能列出约 250 个用例（不需要硬件）。
2. 接上 TaiShan 板，`HW_env=Self-collection`，跑最简单的 `-k "chip and info"`，确认 DLL、FTDI、复位链路都通。
3. 读代码：`engine.py` → `expect.py` → `builtins.py`（前 260 行）→ 每个功能目录挑一个 YAML 对照 `wapis_cmds.py` 里的函数。
4. 接上 UART，跑 `-k "work_mode" --uart-port COMx`，再读 `helpers.py` 和 `stat/test_stat_cases.py`。
5. 有 SongShan 板后，`HW_env=BERT` 跑一个带 `bert_*` 的用例，理解 `builtins_ext/bert.py` 与 `ss_server.py` 的子进程通信。
6. 加 `--allure` 跑一个小 marker（如 `-m clk`），打开生成的 HTML 和 xlsx，熟悉报告结构。

通常不需要改的部分：`validation/`、`libs/`、`ts_mss_ftdi/`、`drivers/`、`core.py`、`wapis_cmds.py`，它们是厂商/内部交付的依赖，升级时整体替换。
