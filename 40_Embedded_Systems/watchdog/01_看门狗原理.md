> [!abstract] 核心结论
> 看完解决几个问题，了解看门狗的原理
> 
> 看门狗到底在防什么？为什么它必须独立？喂狗该放哪？


## 1.1 先划清边界：安全性 vs 活性

可靠性文献里把系统性质分两类，这个划分是理解看门狗的钥匙：

| 性质               | 含义        | 违反的样子                  | 看门狗管不管      |
| ---------------- | --------- | ---------------------- | ----------- |
| **Safety（安全性）**  | "坏事永远不发生" | 算错了、写错了寄存器、把 A 口配成 B 口 | **管不了**     |
| **Liveness（活性）** | "好事最终会发生" | 卡住了、不再前进、永远等不到         | **正好是它的领域** |

> 看门狗是**活性监视器**。它检测不到"算错"，只能检测到"不动了"。 推论：任何指望看门狗兜住逻辑 bug 的设计都是幻觉；反过来，任何"系统偶尔就不响应了、复现不了"的场景，看门狗是第一顺位工具。

## 1.2 会导致"不动了"的六类故障

按你在 Dragon 上实际会遇到的概率排序：

1. **死循环 / 状态机卡死** 等一个永远不会置位的硬件状态位是最常见的一种：

c

```c
   while (!(REG_STATUS & DONE_BIT));   // 对端没上电 → 永远卡这里
```

这类代码在 flash 驱动、I2C/EEPROM 驱动、link training 轮询里遍地都是。

2. **PC 跑飞（PC runaway）** 栈溢出踩掉返回地址、函数指针是野指针、跳进了没映射的地址。 → 有可能进 exception handler 后又在里面挂掉（handler 里再触发 exception = 死循环）， → 也有可能"恰好"落在一段合法代码上继续跑，行为完全不可预测。 这是**唯一一类连 exception handler 都救不了**的故障，只有独立硬件能救。
3. **中断风暴 / 中断丢失**
    - 风暴：外设中断标志没清干净 → ISR 退出立刻重入 → 主循环再也拿不到 CPU。
    - 丢失：等某个中断唤醒，但中断被意外屏蔽（`mstatus.MIE` 没开、PLIC enable 被覆盖）→ 永远等。
4. **RTOS 层的饿死与死锁**
    - 优先级反转：高优先级任务等低优先级任务持有的 mutex，中优先级任务一直跑。
    - 互相等待的两把锁。
    - 某个任务把 CPU 吃满，低优先级任务饿死 —— **注意：此时"系统"看起来是活的**，这正是单点喂狗抓不到、必须多任务签到的原因（见 [[03-喂狗策略与反模式]]）。
5. **外部扰动造成的状态破坏** 电源毛刺、ESD、单粒子翻转（SEU）翻掉 RAM/寄存器里一位。 现象随机、无法复现、无法靠代码审查消除。**这是看门狗最原始的设计动机。**
6. **时钟/电源子系统异常** PLL 失锁、时钟被误关、电压掉到 brown-out 边缘但没触发 POR。 ⚠️ 这一类会直接影响你对"狗的时钟源"的选择 —— 见 [[02-看门狗硬件解剖]] 的 §2.2。

## 1.3 看门狗不能做什么（写下来，避免再走弯路）

- **不能替代断言和错误处理。** 已知的、能判断的错误要当场处理，不要"反正狗会救"。
- **不能当调试器。** 但两段式的第一段中断可以变成一个非常好的"死机现场采样器"——这是让看门狗从"兜底"升级成"可观测性工具"的关键，见 [[08-复位原因与故障现场保存]]。
- **不能保证复位后能恢复。** 如果故障是持续性的（外设挂了、配置数据损坏），复位只会进入无限复位循环。 → 所以必须有**复位计数 + 降级策略**：连续 N 次狗复位 → 进安全模式 / 切 A-B slot / 停在 bootloader 等命令。

## 1.4 放进 Dragon 的语境

Dragon 是 retimer，firmware 的职责是链路管理、EEPROM/flash 参数、健康上报。对它而言：

- "不动了" 的后果 = 上位机读不到状态、link 状态机停在中间态、热插拔事件漏处理。
- 复位的代价 **不是零**：复位可能打断正在工作的链路。 → ⚠️ 必须先确认 **wdt_rst 的复位域**：只复位 CPU 子系统，还是整颗 SoC（含 SerDes / 链路）？ 这个答案直接决定你敢把超时设多短、以及第一段中断里是否值得尝试"软恢复"。 记到 [[11-自检题与待核对清单]]。

## 1.5 本篇要点

- 看门狗只管活性，不管正确性。
- 六类故障里，**PC 跑飞和外部扰动**是只有独立硬件能兜的，其余的软件也能部分覆盖。
- 狗咬之后的故事（复位原因、复位循环、降级）和狗咬之前一样重要。
