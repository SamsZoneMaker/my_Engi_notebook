## 复盘当前中断实现
在使能向量中断功能之前，dragon项目中使用的是软件级别的中断处理方式。以下重新梳理当前的实现方式

### File Map
按"从硬件到应用"的顺序排：

```

         硬件层                    平台层                     应用层  
  ┌──────────────────┐   ┌────────────────────┐   ┌──────────────────┐  
  │ n25f_core.h      │   │ n25f_isr.c         │   │ 你的驱动          │

  │ n25f_plic.h      │◄──┤  mext_interrupt    │◄──┤  spi1_isr()      │

  └──────────────────┘   │ isr.h 中断号枚举     │   └──────────────────┘  
                         │ target_isr.h 抽象宏  │
```

逐个文件的一句话职责：

| 文件               | 职责                                                     | 语言   | 什么时候会改它                     |
| ---------------- | ------------------------------------------------------ | ---- | --------------------------- |
| `brom.ld`        | 告诉链接器"代码放哪、数据放哪、栈在哪"                                   | 链接脚本 | 加新段、改内存大小                   |
| `start.s`        | 上电第一条指令；初始化寄存器/栈/gp，设 `mtvec`，调 `reset_handler`        | 汇编   | 极少                          |
| `trap.s`         | 中断/异常的**第一现场**：保存现场 → 调 C → 恢复现场 → `mret`              | 汇编   | 极少（改了必须同步改 `isr_context_t`） |
| `n25f_core.h`    | CPU 侧定义：CSR 号、`mstatus`/`mcause`/`mip` 各个位、CSR 读写内联    | C 头  | 用到新 CSR 位时                  |
| `n25f_plic.h`    | PLIC 寄存器地址 + enable/priority/claim/complete 内联函数       | C 头  | 加 PLIC 新功能时                 |
| `n25f_plic_sw.h` | 软件中断（MSWI）用的另一个 PLIC 实例                                | C 头  | 极少                          |
| `target_isr.h`   | 把上面两个包一层，给出 `TARGET_XXX` 宏 + `isr_context_t` + 临界区     | C 头  | 加新的 TARGET 抽象时              |
| `isr.h`          | **中断源编号表**（两个 enum）+ 优先级常量                             | C 头  | 芯片中断连接改了                    |
| `n25f_isr.c`     | `trap_handler` 总分发 + `mext_interrupt` + 各种 weak 默认 ISR | C    | 改分发逻辑时                      |
| `platform_isr.c` | 96 个源 → 具体函数的**查找表**；平台/应用分层；`ww_isr_init`             | C    | **加新中断源最常改这里**              |
| `fatal.c`        | 异常时打印寄存器现场然后死循环                                        | C    | 加诊断信息时                      |


### 汇编文件
用于看懂 `start.s` 和 `trap.s` 

#### 寄存器
RISC-V 有 32 个通用寄存器 `x0`~`x31`，但汇编里几乎都用**ABI 别名**：

|别名|编号|用途|谁负责保存|
|---|---|---|---|
|`zero`|x0|永远是 0，写它无效|—|
|`ra`|x1|return address，`call` 自动写入|**caller**|
|`sp`|x2|栈指针|callee|
|`gp`|x3|global pointer，全局变量的快速寻址基址|—|
|`tp`|x4|thread pointer|—|
|`t0`-`t6`|x5-7, x28-31|临时寄存器|**caller**|
|`a0`-`a7`|x10-17|函数参数 / 返回值（`a0`=第 1 参数，也是返回值）|**caller**|
|`s0`-`s11`|x8-9, x18-27|保存寄存器|callee|

**"caller-saved" vs "callee-saved" 是理解 `trap.s` 的关键**：

- **caller-saved**（`ra`/`t*`/`a*`）：约定这些寄存器"调用函数后可能被改坏"， 调用方如果还需要它们的值，自己在调用前存好。
    
- **callee-saved**（`s*`/`sp`）：约定"被调用的函数如果要用，必须先存起来、返回前恢复"。
    

所以 `trap.s` **只保存了 caller-saved 那 16 个**，一个 `s0`-`s11` 都没保存。 不是漏了 —— 因为 `trap_handler` 是一个普通 C 函数，编译器按 ABI 生成代码， 它如果用到 `s0`-`s11` 会**自己**在函数序言里保存、在尾声里恢复。 汇编只需要保管 C 编译器不会替我们保管的那一半。


### 局部数字标号

```asm
1:  j 1b
```

`1:` 是可以重复使用的局部标号。引用时 `1b` = 往**b**ack 找最近的 `1:`，
`1f` = 往**f**orward 找。所以 `j 1b` 就是"跳回自己" = 死循环。

### trap.s
trap.s 是硬件直接跳进来的，没有任何编译器生成的序言，进来的瞬间：
- 所有通用寄存机还是被打断代码的值 -- 动任何一个都会破坏现场
- `sp` 是被打断代码的栈指针（能用，但要小心）
- 中断已被硬件关闭（`mstatus.MIE = 0`）

所以它必须用汇编写：C 编译器无法保证"函数第一条指令之前不碰任何寄存器"。

## 问题与思考
### Q:为什么需要plic
[[N25F 中断机制#PLIC 概述]]有对plic的理论介绍。从项目的角度而言，`isr.h` 中 32 + 95种中断源，而常规的中断源只有3种，所以`isr.h` 所有的中断源都要挤进“外部中断”的这一根线上，这就需要在中断源和cpu之间加一个硬件模块 PLIC(Platform-Level Interrupt Controller，平台级中断控制器)
```
 I2C  ──┐
 SPI  ──┤
 GPIO ──┤            ┌──────────────┐
 DMA  ──┼──96 根线──► │    PLIC      │──1 根 meip──► CPU
 ...  ──┤            │ 扇入/仲裁/优先级│
 PCS  ──┘            └──────────────┘
```
plic在中间做以下的事情：
1. 扇入：把96根线合成一根
2. 过滤：每个源有 enable 位和 priority，priority ≤ threshold 的不上报
3. 仲裁：多个同时来，选优先级最高的
4. 应答：CPU 通过读 claim 寄存器问"是谁？"，PLIC 返回源编号




## 速查
### 汇编指令和伪指令速查
"伪指令"指的是汇编器提供的方便写法，会展开成一条或多条真指令。

| 写法                      | 含义                                  | Remark                 |
| ----------------------- | ----------------------------------- | ---------------------- |
| `li t0, 0`              | load immediate，把常数装进寄存器t0           | 伪指令                    |
| `la t0, sym`            | load address，把符号 `sym` 的**地址**装进寄存器 | 伪指令，展开成 `auipc`+`addi` |
| `mv sp, t0`             | 寄存器搬运                               | 伪指令 = `addi sp, t0, 0` |
| `sw t0, 4(sp)`          | store word：把 `t0` 存到 `sp+4`         | `lw` 是反过来              |
| `csrr t0, mepc`         | CSR read：读控制状态寄存器                   |                        |
| `csrw mepc, t0`         | CSR write：写                         |                        |
| `csrrs t0, mstatus, t1` | 读出来 + **置位**（OR）                    | 用来"只改某几位"              |
| `csrrc`                 | 读出来 + **清位**（AND NOT）               | 同上                     |
| `call func`             | 调用函数（把返回地址放 `ra`）                   | 伪指令                    |
| `j label`               | 无条件跳转                               |                        |
| `bnez t0, label`        | branch if not equal zero            |                        |
| `mret`                  | 从 M 模式 trap 返回（**只有中断/异常返回用它**）     | 不是 `ret`！              |

`ret` 和 `mret` 千万别混：`ret` 是普通函数返回（跳到 `ra`）； `mret` 是中断返回（跳到 `mepc`，并恢复 `mstatus.MIE`）。


### 汇编器的指令

| 写法                                               | 含义                                                         |
| -------------------------------------------------- | ------------------------------------------------------------ |
| `.section .text, "ax"`                             | 后面的内容放进名为 `.text` 的段；`a`=需要分配内存，`x`=可执行 |
| `.global sym`                                      | 把 `sym` 导出，让别的文件能引用                              |
| `.weak sym`                                        | 定义成**弱符号**：如果别处有同名强符号，链接时用别处的       |
| `.type f,@function`                                | 告诉工具链 `f` 是个函数（调试器/反汇编用）                   |
| `.align 3`                                         | 对齐到 2³ = 8 字节边界                                       |
| `.option push` / `.option norelax` / `.option pop` | 临时关掉汇编器的"松弛优化"                                   |
