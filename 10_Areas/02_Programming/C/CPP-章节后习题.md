## 📝 Chapter 1
### 🤔 Q&A
### Q1: 对编程而言，可移植性（Portability）意味着什么？

**可移植性**指的是：**在一种系统（硬件或操作系统）上编写的源代码，能够在不做修改或仅需少量修改的情况下，在另一种不同的系统上编译并运行。**
- **通俗解释**：比如你在 Windows 上写了一段 C 语言代码，如果这段代码具有良好的可移植性，那么你把它拿到 Linux 系统或者 Mac 系统上，只需要用当地的编译器重新编译一下，程序就能正常跑起来，而不需要你重写代码。
- **关键点**：不仅是语言本身的标准统一（如 ANSI C 标准），也意味着程序员在写代码时避免使用了特定系统的专有功能。
<br>
### Q2: 解释源代码文件、目标代码文件和可执行文件有什么区别？

这三种文件代表了程序从“人写的字”变成“机器跑的程序”的三个阶段：
- **源代码文件 (Source Code File)**：
    - **内容**：由程序员使用高级编程语言（如 C、C++）编写的文本文件。
    - **特点**：**人类可读**，但机器无法直接理解和执行。
    - **后缀示例**：`.c`, `.cpp`, `.java`。
- **目标代码文件 (Object Code File)**：
    - **内容**：编译器将源代码翻译成的机器语言（二进制代码）。
    - **特点**：**机器可读**，但**不完整**。它包含了主程序的指令，但缺少启动代码和标准库代码（比如 `printf` 的具体实现），因此还不能直接运行。
    - **后缀示例**：`.obj` (Windows), `.o` (Linux/Unix)。
- **可执行文件 (Executable File)**：
    - **内容**：链接器将目标代码、启动代码和库代码组合后生成的最终文件。
    - **特点**：**完整且机器可执行**。操作系统可以直接加载运行它。
    - **后缀示例**：`.exe` (Windows), Linux 下通常没有后缀。

**总结流程**：源代码 -> (编译) -> 目标代码 -> (链接) -> 可执行文件。
<br>
### Q3: 编程的 7 个主要步骤是什么？

如《C Primer Plus》中定义的编程流程，强调了“先思考，后动手”的重要性：
1. **定义程序目标 (Define the Program Objectives)**：明确你想要程序做什么，需要什么输入，产生什么输出。
2. **设计程序 (Design the Program)**：思考如何实现目标，规划用户界面、数据结构和算法流程（通常使用伪代码或流程图）。
3. **编写代码 (Write the Code)**：将设计好的逻辑翻译成具体的编程语言（源代码）。
4. **编译 (Compile)**：使用编译器将源代码转换为目标代码，并检查语法错误。
5. **运行程序 (Run the Program)**：生成可执行文件并在计算机上运行它。
6. **测试和调试程序 (Test and Debug the Program)**：检查程序是否存在 Bug（逻辑错误），看它是否按预期工作，并修复错误。
7. **维护和修改程序 (Maintain and Modify the Program)**：在程序投入使用后，修复新发现的问题，或者根据需求添加新功能。
<br>
### Q4:编译器的任务是什么？

编译器的核心任务是 **“翻译”** 和 **“检查”**：

1. **翻译**：它将**高级语言**（如 C 语言源代码）翻译成计算机能够理解的**机器语言**（目标代码）。
2. **语法检查**：在翻译过程中，它会检查你的代码是否符合语言的语法规则。如果你写错了关键字或漏了分号，编译器会报错并拒绝生成目标代码。
<br>
### Q5: 链接器的任务是什么

链接器的核心任务是 **“打包”** 和 **“组合”**：

1. **组合**：它把你编译生成的**目标代码**（`.obj` 或 `.o`）与系统的**启动代码**（startup code，告诉系统如何开始运行程序）以及你用到的**库代码**（library code，如 `stdio.h` 里声明的函数的实际二进制代码）结合在一起。
2. **解析引用**：如果在你的代码中调用了 `printf`，编译器只知道有这个名字，而链接器负责找到 `printf` 真正的机器码位置，并将它们连接起来，最终生成一个独立的**可执行文件**。
