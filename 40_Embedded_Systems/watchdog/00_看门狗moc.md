## 一句话心智模型

> **看门狗 = 一个你无法用软件说服的、独立计时的死刑执行者。** 你唯一能做的，是周期性地证明"系统还在有意义地前进"来申请缓刑。 一切设计问题都归结为：**什么叫"有意义地前进"，以及谁有资格代表系统作这个证明。**

寄存器只占这份讲义的两篇。上一轮兜圈子，多半是因为跳过了上面这句话直接去写寄存器。

## 速查卡

### ATCWDT200 寄存器（base = `0xD0800000`）

text

```text
+0x00 IdRev    RO     [31:12]=0x03002  Dragon 实测 IDREV=0x03002004 (rev 0.4)
+0x10 Ctrl     R/WP   [10:8]RstTime [7:4]IntTime [3]RstEn [2]IntEn [1]ClkSel [0]En
                      ★ ClkSel: 0=EXTCLK, 1=PCLK（极性容易记反）
+0x14 Restart  WP     写 0xCAFE：重启中断计时器 + 【取消】复位计时器
+0x18 WrEn     WO     写 0x5AA5：解锁，只管【紧接着的一次】WDT 寄存器写
+0x1C St       R/W1C  [0]IntExpired
```

### 三条铁律

1. `WREN` 后必须**紧跟**被保护的那一条写，中间不能有任何 WDT 写，整体放临界区。
2. **总超时 = IntTime + RstTime**。`IntEn=0` **不会**跳过第一段。
3. 16-bit 计数器下 `IntTime` 只有 `0~7` 合法，上限 2¹⁵。

### Dragon 时间表（EXTCLK = 20 kHz，T = 50 µs，16-bit）

|IntTime|0|1|2|3|4|5|6|7|
|---|---|---|---|---|---|---|---|---|
|ms|3.2|12.8|51.2|102.4|204.8|409.6|819.2|**1638.4**|

|RstTime|0|1|2|3|4|5|6|7|
|---|---|---|---|---|---|---|---|---|
|ms|6.4|12.8|25.6|51.2|102.4|204.8|409.6|819.2|

常用 CTRL：`0x079`→1644.8 ms（只复位） · `0x679`→2048 ms（只复位） · `0x67D`→2048 ms（两段全开）

### N25(F) 中断路由（DS130 Table 101/102）

text

```text
nmi  ← WDT          ★ AE350 参考连接里 WDT 只进 NMI，不进 PLIC
mtip ← Machine Timer
meip ← PLIC          PLIC source 3 = PIT
msip ← PLIC_SW

mnvec (CSR 0x7c3)  = RO = reset_vector 引脚 → NMI 入口 == 复位入口
NMI: mcause=1, mepc=下一条指令, mstatus.MIE←0, 不可恢复
```

## 本项目目标与现状

| 目标                                 | 状态                                 |
| ---------------------------------- | ---------------------------------- |
| ATCWDT200 使能，interrupt + reset 两段式 | 🟡 reset 已通，int 待定                 |
| 裸机驱动（brom / retimer 早期阶段可用）        | 🟡 待整改（[[06_Dragon-裸机WDT驱动]] §6.8） |
| FreeRTOS 多任务 check-in 框架           | 🟡 v7 单 client 台架中                 |
| `wdt_int` 路由确认（NMI vs PLIC）        | 🔵 见 [[07_wdt_int-路由-NMI还是PLIC]]   |
| 复位原因可追溯                            | 🟡 WRSR + `.noinit` 已验证，记录格式待升级    |

> **关键认知**：`wdt_int`/NMI **只影响诊断，不影响保护**。 硬件复位由第二阶段独立计时，NMI 进不进得来都照样复位。 把 NMI 挪出关键路径，保护主线（supervisor）可以并行推进 —— 这是防止再次兜圈子的最重要一条。

## 当前最该做的三件事

1. **实验 B**（半小时）：一次锁定魔数 / `RstTime` 位宽 / 计数器宽度 / 写保护语义
2. **实验 C**：只中断不复位，量出真实 TintT_{int} Tint​，验证 EXTCLK 真的是 20 kHz
3. **v8**：把 `vdc_task_handle_proc_rqst()` 和 `init_ctrl_boot_dld_check()` 的最坏耗时**测出来** —— v7 里的 `deadline = 1000 ms` 目前是猜的，后面所有配置都建在它上面

三件事互相独立，可并行，都不需要先解决 NMI 问题。
